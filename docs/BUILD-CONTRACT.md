# RATCHET — Build Contract (internal, read by every builder)

**Product name:** Ratchet — an autonomous-but-gated delivery harness for Claude Code projects.
Tagline: *the run moves forward or it stops; it never quietly slides back.*

This file is the shared source of truth for everyone building Ratchet. Every name, path, exit code
and format below is FROZEN. If you need something not listed here, invent it inside your own file
and note it in your report — do not redefine anything that is listed.

---

## 0. Non-negotiable build rules

1. **POSIX/Git-Bash safe.** Target bash 4+. The primary deployment host is **Windows/Git-Bash**, and
   Linux/macOS second. Therefore:
   - No `flock`, no `mapfile`, no associative arrays unless guarded, no GNU-only flags.
   - Process substitution `<(...)` is allowed (bash) but prefer temp files where easy.
   - Always `command -v X >/dev/null 2>&1` before using a non-core tool.
   - Never assume `python` — use the interpreter probe (`rt_pick_py`, §4.1).
   - Handle CRLF: strip `\r` when reading any file that a Windows editor may have touched.
2. **Python 3.8+.** Every `open()`/`read_text()`/`write_text()` MUST pass `encoding="utf-8"`.
   Every script that prints non-ASCII MUST call the stdout reconfigure shim (§4.2).
   No third-party imports. Standard library only.
3. **Fail closed.** A guard that cannot determine safety BLOCKS. A missing dependency at a
   security-relevant gate BLOCKS. Never fail open with a warning.
4. **Decide by effect, never by verb token.** A rule protecting a path must consider redirects
   (`>`, `>>`), copy/move/link verbs, `sed -i`, `tee`, `dd`, `truncate`, and heredocs — not just an
   allowlist of "write commands". Order write-effect checks BEFORE read carve-outs.
5. **No hardcoded project nouns.** Every project-specific string comes from config. Grep your own
   output for `kalshi`, `trading`, `crypto`, `bitcoin` — zero hits allowed.
6. **Every check must be able to fail.** If you write a check, write the input that makes it fail.
   A check that only emits PASS/WARN is not a check.
7. **Reader and writer change together.** If you write a state file, you own its reader; document the
   exact format in a comment block at the top of the writer.

## 3. Hook wiring and exit conventions

| Event | Matcher | Script | Block mechanism |
|---|---|---|---|
| `SessionStart` | — | `session-start.sh` | stdout JSON `{"hookSpecificOutput":{"hookEventName":"SessionStart","additionalContext":"..."}}` |
| `PreToolUse` | `Bash` | `guard.sh` | **exit 2** + reason on stderr |
| `PreToolUse` | `Edit\|Write\|NotebookEdit` | `scope-guard.sh` | **exit 2** + reason on stderr |
| `PostToolUse` | `Edit\|Write` | `format.sh` | never blocks; always exit 0 |
| `SubagentStop` | `developer` | `subagent-gate.sh` | stdout JSON `{"decision":"block","reason":"..."}` |
| `SubagentStop` | `test-writer` | `red-gate.sh` | same |
| `Stop` | — | `stop-gate.sh` | same |
| `Notification` | — | `notify.sh` | never blocks |

**Every hook reads its payload as JSON on stdin.** Use `jq` when present; every hook must degrade to
a `sed`/`grep` extraction for the *non-security* fields only. For security decisions, **absent jq =
BLOCK** (this is the `fragile-consent-parse` fix).

Manual (agent-invoked, allow-listed) scripts: `dispatch-baseline.sh`, `checkpoint-evidence.sh`,
`gc-prune.sh`, `escalate.sh`, `pipeline-event.sh`, `proof_map.py`, `run_metrics.py`.
Human-only (denied to agent at 3 layers): `approve.sh`.

### 4.1 Interpreter probe (copy this behaviour exactly)
Try in order: `$RATCHET_PYTHON`, `python3`, `python`, `py -3`. For each candidate, run
`<cand> -c "import sys;print(sys.version_info[0])"` and accept only if it prints `3`. The Windows
Store stub exits non-zero / prints nothing — this is what the probe exists to skip. Cache the result
in `.pipeline/.py-interp` per host.

### 4.2 Python stdout shim (first lines of every .py)
```python
import sys
if hasattr(sys.stdout, "reconfigure"):
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
    sys.stderr.reconfigure(encoding="utf-8", errors="replace")
```

## 5. Behavioural contracts

### 5.1 Run lifecycle — ONE origin, scripted transitions
`gc-prune.sh` owns all four transitions. No other script writes these files.
```
gc-prune.sh start <milestone>   -> writes RUN_ACTIVE (milestone id), RUN_START (epoch), zeroes RUN_IDLE
gc-prune.sh reopen              -> re-arms an archived run WITHOUT resetting elapsed work
gc-prune.sh archive <milestone> -> archives manifest+journal, clears RUN_ACTIVE/READY_TO_SHIP,
                                   expires all escalation approvals, rotates EVENTS_LOG
gc-prune.sh prune               -> scratch hygiene only
```
**With no run active, every scope check and the Stop gate's definition-of-done checks are INERT.**

### 5.2 Gate tiers (stop-gate)
- no `RUN_ACTIVE` → inert, allow stop.
- `RUN_ACTIVE` and no `READY_TO_SHIP` → **intermediate tier**: fast suite + scope check only.
- `READY_TO_SHIP` present → **ship tier**: `VERIFY_CMD` (writes `VERIFY_LAST`) + `check_done.py` +
  scope check + retry cap + repeat-failure hash stop.
`VERIFY_LAST` schema: `{"tier","head_sha","dirty_hash","exit","tail","timestamp"}`. Nobody re-runs
the suite to learn something already in this file.

### 5.3 Budget = WORK, not wall
`RUN_LAST_SEEN` updated on every hook firing. On each update, if `now - last_seen >
IDLE_THRESHOLD_SECONDS`, add the gap to `RUN_IDLE`. `work = (now - RUN_START) - RUN_IDLE`.
The Stop gate halts on `work > MAX_RUN_WORK_SECONDS` or `wall > MAX_RUN_WALL_SECONDS`.
**No script may edit `RUN_START` to clear a halt** — say so in a comment.

### 5.4 Attribution — three named modes, degrade loudly
1. **exact** — a dispatch baseline exists (`dispatch-baseline.sh` wrote a tree snapshot for
   `$PIPELINE_DISPATCH_ID`): diff against it.
2. **sound** — a partition glob is on disk for this dispatch: a path outside the glob is provably
   not this agent's (scope-guard refused every write outside it).
3. **weak** — forbidden-path filter only. **Prints that it is weak.**
**In any mode below `exact`, a gate REPORTS an out-of-scope file; it NEVER orders a revert.**

> **Env-var caveat (measured):** `PIPELINE_DISPATCH_ID` / `PIPELINE_PARTITION_GLOB` do NOT reliably
> reach hook environments from the Agent tool. Therefore the orchestrator writes them to disk:
> `.pipeline/dispatch/<id>.glob` and `.pipeline/dispatch/current`. Hooks read the FILES, and treat
> the env vars as a fallback only.

### 5.5 Escalation modes
- **light (default).** Two classes: *never-escalatable* (hard wall) and *confirmable* (the guard
  refuses, prints `This refusal is ESCALATABLE (id=<id>)`, and a human confirms by running
  `approve.sh <id>` in their own terminal). Approval is single-use, TTL-bound, run-bound and
  byte-bound, but the confirmable class is broad and the never class is small.
- **strict.** Same mechanics, but the confirmable class shrinks and more rules move to never.
Both modes use the same HMAC machinery. The MAC covers
`version|id|rule|tool|target_sha|run_token|expiry`. Key is read by path (never argv), 0600.
`approve.sh` requires a TTY and refuses never-escalatable ids.
**Disclosure:** `approve.sh --disclose <check-id>` binds to the *failure text*, renders **DISCLOSED**
(never PASS), is excluded from the exit code only, is reprinted in full at every subsequent block,
and dies at gate closure.

### 5.6 Never-escalatable core (harness-fixed, plus `DOMAIN_NEVER_ESCALATABLE`)
secrets/keys/`.env` · force push · push or commit to `BASE_BRANCH` outside the ship flow ·
the governing corpus (`GOVERNING_CORPUS`) · the control set:
`settings.json guard.sh scope-guard.sh hooklib.sh escalation-lib.sh approve.sh ratchet.config.sh`

**Plus the harness's own state stores**, which are the control set seen from the other side — an
approval means nothing if the agent can edit the thing the approval is written into, or the thing
that defines the approval's own scope: `escalation-store-write` and `escalation-state-write`
(`$ESCALATIONS_DIR` — the ledger and the approval records), `dispatch-store-write` (`$DISPATCH_DIR`
— the partition globs the scope check reads and the baselines the gates attribute with), and
`approve-script-invocation` (invoking a control-set file *is* a control-set operation).

Nothing lifts any of these. Not an approval, not a card, not a domain pack. The canonical list is
`ESC_NEVER_CORE` in `escalation-lib.sh`; this section and that variable change in the same commit.

### 5.7 Ship flow (two factors + a record)
1. Affirmative selection on an `AskUserQuestion` Ship Prompt card.
2. The tool-permission approval on the merge command itself.
3. `SHIP_CONSENT` written BEFORE the merge:
   `{"pr","head_sha","base","question","options_offered","answer","answered_at"}`.
`guard.sh` refuses `gh pr merge` / any push to `BASE_BRANCH` unless the consent file exists and its
`pr` + `head_sha` match the command and HEAD. State plainly in comments: this file is a **record**,
not the control; branch protection is the control.

## 6. Naming doctrine (owner directive — implement, don't just document)

Findings, lessons, decisions, pending actions and refinements are referenced by **name**, not code.

- Format: kebab-case, 2–5 words, `^[a-z][a-z0-9]*(-[a-z0-9]+){1,4}$`.
- Must state the problem: `gate-blames-wrong-actor`, not `issue-3`.
- Rejected as too generic (hard list): `fix-issue fix-bug misc-problem update-thing general-fix
  various-fixes minor-issue small-fix quick-fix todo-item` and any name matching
  `^(fix|update|change|misc|various|general|temp|new|old)-`.
- Multi-step efforts: one name plus a step counter — `harness-adjustment-1`, `harness-adjustment-2`.
  Regex: `^<name>-[0-9]+$` where `<name>` itself is valid.
- **Permanent. Never reused, never renamed.** A superseding item gets a NEW name plus a
  `Supersedes: <old-name>` line.
- Uniqueness is checked mechanically at filing time across `FINDINGS`, `ACTIVE_LESSONS`,
  `PENDING_ACTIONS`, and `DECISIONS.md`.
- Decisions keep a numeric id **and** carry a name: `DEC-007 · fee-bound-tightened`. The number is
  the sort key and the archive filename; the name is what humans read and cite.
- WIN rows keep positional ids (`WIN-M1-03` is a coordinate) and gain a `name` column.

`rt_name_valid` (shell) and `check_narrative.py --validate-name` (python) implement the SAME rules.
Write a round-trip test that proves they agree on a shared fixture list.

## 7. Artifact formats (parsers exist — freeze these)

1. **WIN row** (MILESTONES.md table): `| WIN-M<n>-<nn> | <name> | <requirement ids> | <verify command> | <evidence path> |`
   Verify command must be script-decidable (exit 0 = pass). A row with no verify command is a
   **setup defect** — it is raised, never adjudicated.
2. **Proof map**: contracts table with frozen column names `win` and `selector`; output
   `docs/evidence/M<n>/proof-map.md`; every WIN row must collect ≥1 test.
3. **DECISIONS entry**:
   ```
   ## DEC-nnn · <name>
   **Date.** YYYY-MM-DD · **Status.** ACTIVE | SUPERSEDED by DEC-mmm
   **Decision.** <=120 words
   **Default/config.** <key = value>          (omit if none)
   **Supersedes.** DEC-nnn · <name>           (omit if none)
   **Affected.** <requirement ids>
   **Simulated.** Simulated against <n> frozen rows; <k> changed meaning: <list>
   **Archive.** .context/archive/decisions/DEC-nnn-full.md
   ```
   Hot file soft cap 250 lines / hard cap 300. **Appending a decision must never be the failing
   action** — over the hard cap the checker emits a ROLLOVER-REQUIRED warning and the guard still
   permits the append.
4. **findings.md ledger** (pipe table, header frozen):
   `| name | source | severity as filed | file:line | finding | disposition | rationale | DEC |`
   Severity-as-filed is never edited. Dispositions: `FIXED ACCEPTED DEFERRED WAIVED`.
   FIXED rationale ≤ `CAP_RATIONALE_FIXED` words; ACCEPTED/DEFERRED/WAIVED ≤
   `CAP_RATIONALE_ACCEPTED` words **and a DEC id is mandatory**. No probe transcripts in cells.
5. **Board raw outputs**: `.pipeline/reviewer-findings.md`, `.pipeline/security-findings.md`;
   one numbered finding per item, `1.` at line start.
6. **Manifest**: `PLAN_FILES` one path per line. `AMENDMENTS` lines:
   `<path> <DEC-id> [note]` — one shared parser for the Stop gate and `check_done.py`.
7. **Checkpoints**: `.pipeline/checkpoints/<n>-<stage>-jump.md` (7 sections, ≤500 words),
   `-evidence.txt` (script-written only), `-clear.md` (self-written, ≤200 words, names its
   spot-check, final line alone: `CLEAR` / `BLOCK: <reasons>` / `ESCALATE: <reason>`),
   `-fast.md` for FAST checkpoints.
8. **Recap** (`.pipeline/recap.md`): exactly five `## ` headings, in order —
   `What got done` / `Where the project stands` / `What's next` / `Issues you should know about` /
   `How close to launch`. ≤ `CAP_RECAP_WORDS` words total.
9. **Events**: `.pipeline/run-events.jsonl`, one object per line:
   `{"ts","type","run","milestone","kv":{...}}`. Metrics use **null, not zero**, for "not
   instrumented" — a zero must mean measured-zero.
10. **Retro**: `.agent-development/runs/NNN-<milestone>-<outcome>.md`; outcome token set is CLOSED:
    `shipped nogo halted abandoned superseded awaiting-ship`. ≤ `CAP_RETRO_LINES` lines.

## 9. Deliverable style

- Shell: `#!/usr/bin/env bash`, `set -uo pipefail` (NOT `set -e` — see the dead-trap finding), a
  header comment naming the file's contract, functions prefixed per §4.
- Python: module docstring, `argparse`, exit codes documented, `if __name__ == "__main__":`.
- Markdown: no emoji; tables where they carry data; every doc opens with what it is and who owns it.
- Every file that a human must edit says so in its first three lines.
