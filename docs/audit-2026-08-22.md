# Ratchet — external audit, 2026-08-22

**Scope.** Full read of the shipped tree at v1.2.1 (git clean at `7e69c41`), all 28 hooks, 13 agent seats, 4 doctrine docs, `.context/`, `.agent-development/`, the installers, and both `docs/` references — audited against the owners' stated goals: **hands-off operation**, a **self-learning loop**, and **easy reference to context and work history**.

**Method.** Every headline claim below was verified against code (file:line), not docs. The full suite was reproduced in a clean Linux container: **180 run, 173 passed, 0 failed, 7 skipped in 81s** — matching HANDOFF. The two CRITICAL findings were additionally re-verified by hand after independent review passes disagreed.

---

## Verdict in one paragraph

The bones are unusually good: fail-closed guards, effect-not-verb write detection, the lesson→test binding machinery in `test_hooks.py` (every seeded lesson resolves to a live test class whose negative probes are *executed in-process* — a real answer to "a check that only passes is theater"), pointer-discipline in the subagent seats, and the INDEX/DECISIONS register designs. But measured against your three goals, the harness today is roughly **half a loop wearing a full loop's documentation**. The learning loop's read-side works; its write-back side (retro → INDEX → consolidation → ACTIVE-LESSONS) is enforced by *prose only*, and the one gate-side reader of the lesson ledger cannot parse the ledger the harness ships — your own `reader-writer-drift` lesson, live in the artifact that teaches it. Hands-off operation is structurally blocked by design choices that are individually defensible ("never proceed on silence") but combine with default-off paging into a system that stalls silently when unattended. And the 1.2.0 partition cleanup did not actually land in the shipped tree: five stale doctrine files still sit in `harness/.context/`, the installer's own comment says three files while its glob copies eight, and the updater then protects the stale copies as USER files forever.

## Against your three goals

### Hands-off

The honest current state: this is a *supervised* harness with excellent refusal semantics, not yet a hands-off one. Four things stand between you and "kick it off and walk away." First, nothing self-starts or chains — every run and every milestone begins with a human pasting a prompt into a fresh session. Second, the only way to lift a refusal is a human at a TTY in a separate terminal retyping an id; the approval artifact itself is already file-based HMAC (good — that means an async/remote approval channel is a small build, not a redesign), but the minting is TTY-locked and the signature expires in 30 minutes and dies at archive, so an overnight approval is void by morning. Third, "never proceed on silence" is the right default *only if silence pages someone* — today the pager is off by default, the three setup rows that would tell you so are filtered out by the recurrence threshold, and stall detection is substring-matching on notification text rather than watching the escalation ledger. Fourth, three separate paths (unwritten contracts, wall halt, `gh` auth expiry) end a run quietly in a way that looks like success.

### Self-learning

The loop is documented end to end and instrumented halfway. What genuinely works: `session-start.sh` reliably feeds `ACTIVE-LESSONS.md` into every session, and the lesson→test bindings are the strongest artifact in the repo — all ten seeded lessons resolve to real test classes with executed negative probes and a frozen name map that fails on rename. What does not: the gate never checks that a retro or INDEX row exists (R2), nothing schedules or verifies consolidation (R4), the metrics sidecar that would let a retro measure its predecessor's refinement is never written (R8), and the gate-side lesson parser cannot read the ledger at all (R1). Net effect: lessons flow *out* of storage into sessions, but nothing mechanically guarantees lessons ever flow *in*. The loop closes only if every future orchestrator follows prose perfectly — which is precisely the failure mode the nine-run corpus paid for.

### Context and work history

The seat-level pointer discipline is excellent and worth protecting. The orchestrator side is heavy and partially self-defeating: ~30k tokens of mandatory reading per session, two files loaded twice, both size caps defeated by the import path, and a shipped `.context/` that contains a second, older, self-consistent chain of the same doctrine with contradictory ownership headers — authoritative-looking wrong answers one glob away from any exploring agent. History is archived safely (scope-exempt, never pruned — good) but is write-only in practice: no reader, no index over decision archives, no name→id map, no cross-run metrics by explicit design. "Easily reference work history" today means "grep and hope."

## Recommended sequence

Ordered by leverage; items 1–4 are small, scoped, and each makes an existing documented promise true rather than adding surface. Per your own rule, land them one commit at a time with the suite between.

1. **Fix `parse_lessons` (R1)** to accept `^###?\s+` and backticked/inline `assert:`, and — the actual lesson — swap its selftest fixture to a copy of the *real shipped ledger*. This revives check 14, check 17, and the deepest check in the gate.
2. **Add the retro/INDEX check (R2)** — `runs/NNN-*-<token>.md` exists for this run, token in the closed set, matching INDEX row present — and **move `ready-to-ship` after retro dispatch** (R10). Three docs already claim this check exists; make them true.
3. **Purge the stale five from `harness/.context/` and replace the install glob with a three-file allowlist (R3)**; add updater migration that detects a legacy `.context/CLAUDE.md` import in root `CLAUDE.md` and reports it loudly. This deletes ~30k tokens of contradiction from every future install.
4. **Make silence page by default (R5)**: seed the three pending rows at `recurrence 3` (or always print `filed: install` rows), add the webhook probe row 64 already claims exists, and drive paging from the escalation ledger / `WIP-ESCALATED` state instead of message substrings. Make the "gate allowed the stop after 3 retries" path (R6) send a page unconditionally — it is the single most success-shaped failure in the system.
5. **Enforce consolidation cadence (R4)**: a check that FAILs when `count(runs/) % 5 == 0` with no matching `consolidated/` doc. Also reconcile `retro.md` with the template and restore the "INDEX row last" instruction into the agent prompt (R10).
6. **Wire the metrics sidecar (R8)**: have the retro dispatch run `run_metrics.py` with an `--out` into `.agent-development/metrics/NNN-<milestone>.json`, or delete the prior-column ask from the template. Then a 20-line reader ("last 5 runs: escalations, red-gate rounds, work-seconds") gives you the first real trend view.
7. **Trim the session load (R9)**: drop the `@TEMPLATE.md` import (SPEC/MILESTONES already point to it on demand), drop the `@context-live` / `@ACTIVE-LESSONS` imports (session-start already injects both, capped), cut `DECISIONS.md:11-70` to a pointer. ~8k tokens per session back, no behavior change.
8. **Toward true hands-off (R7)** — the one genuinely new build, and worth doing only after 1–6: an async approval channel (the HMAC file already supports it; what's missing is a minting path that isn't TTY-locked — e.g. a signed approval over the webhook return path or a polled inbox file with a longer TTL that survives archive), plus a thin run-driver that starts the next milestone when the previous one ships and pages instead of parking when it can't. Keep both declared stop points exactly as they are; the goal is removing the *undeclared* ones (per-milestone hand-starts, TTY approvals), not the two that are the product.
9. Then the HANDOFF list stands as written: real Windows PowerShell execution, a first real milestone (expect it to find what the suite cannot — R1/R2 are exactly that class), `local-patch.sh` (wire it or amend UPGRADING §5), `COMMIT_SCOPE_LINES`, and the doc corrections in R11.

## Do not undo

The seeded lessons and their binding machinery (strongest part of the repo), the two declared stop points, the four-directory partition (the fix in item 3 *restores* it), fail-closed guard semantics, effect-not-verb ordering, and the seats' pointers-not-payloads discipline. Nothing above requires touching any of these; most of it consists of making the code do what the documentation already promises.
