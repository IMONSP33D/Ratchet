The verdict

The point was missed in a specific, diagnosable way, and it is not a taste problem. You built a system whose definition of done is the paperwork exists, handed it to an agent, and the agent — correctly, ruthlessly — maximised paperwork.

Look at what check_done.py actually gates on. Check 16 verifies that five exact headings appear in the recap. Check 19 fails if a file is missing from consolidated/. A FULL checkpoint passes when a file's last line reads the literal string CLEAR. The mandatory spot-check — the one the prompt says the verdict is void without — is enforced by zero lines of code.

Nine of the twelve pipeline seats write documents that no code reads. Every gate that fires, fires on a filename. So the thing produced 80,250 words, twelve seats, four checkpoint tiers, and forty-five artifacts per run, and zero delivered milestones. That is not an agent with a verbose personality. That is an agent with a reward function, doing exactly what the reward function said.

The agent talks too much because you pay it in documents.

Everything below follows from that. The security model is over-scaled because a threat model is a document. The installers are 9,172 lines because thoroughness is a document. The doctrine is 37,920 words because rigour, expressed as prose, is a document. None of it was ever pressure-tested by a run, because a run is the only thing here that can return no.

02

The security model is aimed at an adversary that does not exist — and it has cost you real safety

This is the most expensive mistake in the tree, and the one you asked about. It is not that the security is excessive. It is that the excess produced three live defects, all of which make the system less safe than doing nothing would have.

Name the adversary out loud

The threat actor is an LLM the user launched, on the user's machine, on the user's repo, with the user's credentials, in a terminal the user is sitting at. It has no motive, no persistence, and no second session to coordinate with. What it has is a context window and a strong tendency to take the shortest path to green.

"Shortcut-taking process" and "hostile intelligent adversary" are different engineering problems with different solutions. The tree solves the second one. Read the design intent in the code's own words:

Threat modelThe harness models a deliberately deceptive agent running a confused-deputy attack on its own operatorescalation-lib.sh:832

"THE ATTACK THIS CLOSES. Refusal records live under $ESCALATIONS_DIR, which is inside $PIPELINE_DIR — agent scratch. So the bytes approve.sh shows a human are, on their own, only as trustworthy as the directory they sit in: an agent could get a benign command refused, then rewrite <id>.payload so the human reads something harmless and signs something else."

The mitigation shipped for this is: HMAC-SHA256 over a content-derived id, plus a TTL, plus a run-token binding, plus single-use enforced by atomic rename, plus single-use enforced again by an append-only ledger, plus a postcondition marker with a remedy-command allowlist. Six mechanisms so one human can say yes to their own agent, once.

The HMAC is hand-rolled from RFC 2104 primitives — 128 printf subprocesses XOR-ing a key against ipad/opad — because piping the key through openssl -hmac would put it in argv. On a machine where the "attacker" already has ps and /proc. hmac.new() is called eleven lines above.

Not theoretical. Each of these was run against the code in your tree today.

Defect 02 · VerifiedForce-push to the base branch is allowed by a missing colonguard.sh:430

force-push is classified never-escalatable — the strongest guarantee the system offers. The token list that enforces it:

--force|-f|--force-with-lease|--force-with-lease=*|--force-if-includes|+*:*|--delete|-d)

# +*:* requires a colon. These all pass:
git push origin +main              # force-push to base
git push origin :refs/heads/main   # delete base branch remotely
git push origin --all
git push --mirror origin
git update-ref -d refs/heads/main

settings.json already denies Bash(git push --mirror:*) and Bash(git push --all:*) natively, at a layer with no tokenizer to fool. The 4,008 lines of guard.sh + scope-guard.sh + hooklib.sh + escalation-lib.sh are a second, leakier copy of ~45 lines of JSON. Deleting them makes the never-escalatable set stronger.

What is genuinely good — keep exactly this

  • red-gate.sh. Mechanically proving the tests were red before the implementation existed is the single best control in the system and it is rare to see done properly. Do not touch it.
