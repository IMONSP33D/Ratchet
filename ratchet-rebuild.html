New findings

Seven, ranked. The first two change the architecture, not just the line count.

01 · ReproducedThe stop gate fails open. Block, block, block, ship.stop-gate.sh:107, :509, :519

The Stop hook's terminal paths — retry cap exhausted, and identical-failure-with-unchanged-tree — both call _allow. _allow() { exit 0; }. Exit 0 from a Stop hook means the session is permitted to stop.

_allow() { exit 0; }        stop-gate.sh:107

if [ "$n" -ge "$cap" ]; then
  printf 'ratchet: STOP - the stop gate has blocked %s times...' >&2
  _event stop_gate_cap_exhausted ...
  _allow                  ← definition of done NOT met
fi

reproduced at ship tier from a clean install:
  stop #1 -> BLOCKED
  stop #2 -> BLOCKED
  stop #3 -> BLOCKED
  stop #4 -> *** ALLOWED TO STOP ***
  failing checks at that moment: gate-artifact, manifest-scope, win-rows,
  findings-ledger, ship-report, checkpoints, context-current, escalations,
  recap, retro-filed          ← ten of nineteen

The message goes to stderr, which the model does not reliably surface. Combined with finding 03 — which makes green unreachable — every run reaches this cap by construction. The product's one-line thesis is "the run moves forward or it stops; it never quietly slides back." Its terminal gate quietly slides back on attempt four.

The fix is a deletion, not a patch. Claude Code already caps Stop hooks at eight consecutive blocks and hands control back itself. You do not need MAX_STOP_RETRIES at all. Delete it. If a cap is ever wanted, its exit must be a block carrying a give-up reason — never an allow.

02 · ArchitectureThe TDD ordering invariant is enforced by nothing, and cannot be enforced where you put itsettings.template.json:280,290

Good news first: SubagentStop does support an agent-name matcher, and "matcher": "test-writer" is an exact string match. That part of the design is correct and I expected it not to be.

The problem is what blocking there does. Per the platform docs, exit 2 on SubagentStop prevents that subagent from stopping — it sends the finishing agent back to work. It does not touch the parent's control flow, and it cannot prevent the parent from dispatching developer on its next turn.

So red-gate.sh enforces "test-writer must not finish until its tests are red." Useful. It does not enforce, and structurally cannot enforce, "developer must not start until red was proven." That second sentence is the entire TDD claim of the product, and no mechanism in the tree implements it.

the only lifecycle point that can refuse a dispatch:

"PreToolUse": [{
  "matcher": "Agent",
  "hooks": [{ "type": "command",
              "if": "Agent(developer)",
              "command": "$CLAUDE_PROJECT_DIR/.claude/hooks/sequence-gate.sh" }]
}]

and it is unbypassable — PreToolUse deny outranks every permission mode,
including bypassPermissions and --dangerously-skip-permissions.

The corrected shape is four hooks where you have two: arm a baseline at SubagentStart, verify red at SubagentStop, refuse the developer dispatch at PreToolUse on Agent, verify green at SubagentStop. Only the third one is a sequencing gate. It is ~40 lines and it is the most valuable code in the rebuild.

03 · ReproducedA clean install can never go green — three permanent failures, all self-inflicted

Check 13 — the installer itself runs approve.sh --init-key, which writes a ledger line tagged rule: "escalation-key-access". check_done.py reads rule from every ledger line without looking at event, and that rule is never-escalatable. Permanent: the ledger is append-only by design and gc-prune.sh explicitly refuses to rotate it. Rotating the key makes it worse — you then get a second failure for "escalated twice." No test covers it: grep key_initialized test_hooks.py returns nothing.

Manifest scope — every file the installer wrote is uncommitted, so the first Stop reports all 47 harness files as outside the manifest. Alongside them: uv.lock and __pycache__/*.pyc, created seconds earlier by the gate's own test run, then reported as violations by the same invocation. The generated .gitignore covers secrets/ and .pipeline/ and has no entry for __pycache__, *.pyc, uv.lock, or node_modules/ — the installer knows the stack and the gitignore generator never asks.

The generic stack — proof_map returns SKIP with no collector, and check_done.py converts that skip into a hard FAIL. Every language without a pack, and every monorepo (which detects as generic), is non-shippable. The README says gates "skip with a loud notice rather than silently pass." They fail.

04 · ReproducedEvery non-Python project silently runs pytestinstall.sh · ratchet.config.sh:208

ratchet.config.sh selects the stack from RATCHET_STACK, else a stack/active marker, else python-pytest. Neither installer ever writes stack/active — zero occurrences in install.sh and install.ps1. The detected stack goes into settings.json._ratchet.stack as metadata and into template substitution, and nothing the runtime reads.

real install into a node repo:

Not a loud fallback — python-pytest.sh exists on disk, so the generic-fallback notice never fires. The gate runs pytest in a JS repo, gets exit 4, and blocks the ship on a failure unrelated to the code. A one-line fix today; in the rebuild the whole indirection goes away.

05 · ReproducedThe human's "sacred invariant" reaches zero of twelve agentsinstall.sh:1676 vs _LAWS.md:54

The interview asks for domain laws 3–6, a review lens and a security pass. _LAWS.md:54-63 specifies the substitution contract as <!-- DOMAIN_LAW_n --> markers. The installer's engine is re.compile(r"\{\{([A-Z0-9_]+)\}\}"). The two syntaxes never meet, so every agent ships the generic default.

Three layers of verification miss it. The human's prescribed check is grep -rn "{{", which returns clean. The installer's own unresolved-marker warning uses the same regex. Six of seventeen interview prompts produce output no reader consumes, including SECURITY_BOUNDARY_FILES, which three separate documents describe as driving a Hard Stop.

REPO_ROOT is honoured from the environment and then exported. The test suite pins CLAUDE_PROJECT_DIR to a throwaway repo and documents that pin as the thing it guards — but REPO_ROOT outranks it. Then it goes green. Not because anything was fixed — because the stop-lastfail file it just wrote makes the next probe hit the identical-failure path from finding 01, which exits 0. The availability monitor reports healthy precisely when the thing it monitors has given up.

07There is no orchestrator

Twelve agent seats, and nothing drives them. No .claude/commands/, no skill, no dispatch table. The entry point is a prompt the installer prints and asks you to paste — and the installer prints a different prompt than QUICKSTART.md does. The pipeline's stage order, the seat assignments and the baseline calls are prose in PIPELINE.md addressed to whatever model happens to read it. This is the single biggest gap between what the docs describe and what exists, and it is also the easiest to close: it should be a skill.

Credit where dueThe deny list is the best-built artifact in the repositorysettings.template.json

78 entries. Every Write() path deny has an Edit() twin — the exact mistake most hand-written configs make, since Claude Code only consults Edit() and Read() path rules and silently ignores Write() ones. Correct force-push family coverage. A coherent, documented rationale for why the allow list deliberately permits things the guard then refuses.

Which is the whole argument for the rebuild: the 300 lines of JSON are right and the 4,008 lines of bash re-implementing them are wrong. Keep the JSON. (One real gap: four Read() denies have no Edit() twin, so NotebookEdit is not covered on those paths. Low severity, one-line fix.)

02

The architecture

One decision removes most of the code: Ratchet is a Claude Code plugin plus a small stub committed to the repo. Not an installer.

The platform now ships the distribution problem you spent 9,172 lines solving. A plugin carries hooks, subagent definitions, skills, MCP servers and executables; it installs from a marketplace, pins and bumps its own version, auto-updates in the background, and registers for a whole team from two keys in the repo's settings.json. No copy engine, no manifest, no checksum baseline, no rollback script, no updater, no PowerShell port.

What a plugin cannot do — this is the whole remaining bootstrap

  • Ship a permission surface. A plugin's settings.json supports exactly two keys, and neither is permissions. Deny rules must be a file in the repo. This is the one thing that still has to be written into a user's tree, and it is ~120 lines of JSON.
  • Carry hooks on agent frontmatter. Plugin-shipped agents get hooks, mcpServers and permissionMode stripped. Keep gates in hooks/hooks.json, which survives plugin packaging — and note frontmatter hooks are silently dead in claude -p anyway, so the settings-style placement you already chose is the more robust one.
  • Express deny-with-exceptions, state-dependent policy, or cross-tool sequencing. "Changed files must be a subset of the manifest" and "no developer dispatch before red" are not pattern matches. These are exactly the hooks that survive.

03

The contract

The WIN row is a good idea implemented as a comment. Nothing runs it.

The doctrine says every WIN row is "script-decidable: it has a verify command that exits 0 or non-zero, and a human never adjudicates it." Here is the complete enforcement of that sentence, and it is the only line in the codebase that reads a verify cell:

ReproducedThe verify command is a string in a table that no process ever executescheck_done.py:711
for r in rows:
    v = r["verify"].strip().strip("`")
    if not v or v in ("-", "n/a", "TBD"):
        problems.append("%s has no verify command ...")

so these both PASS:
  | WIN-M1-01 | ... | review the logs and confirm | ... |   ← TEMPLATE.md's own example of an INVALID row
  | WIN-M1-02 | ... | false                       | ... |

and the evidence file is checked harder than the command:
  exists · non-empty · git-tracked — but never compared to any command's output.
  echo "PASS - looks good to me" > docs/evidence/M0/win.txt   ← satisfies it

Two more breaks in the same chain. The Requirements column is never extracted — cells[2] is not read, and no code resolves a REQ- id against anything. And the real WIN→test binding lives in .pipeline/contracts.md, written by the architect, in agent scratch, reconciled against the human's MILESTONES.md by nothing. A row present in the human's file and absent from the agent's table passes with zero tests, and the gate prints ">=1 test per row" while covering fewer.

The incentive that creates is the worst part: a row that resists testing is best handled by dropping it from the agent-written table, where it silently passes.

Two inversions fix it

  1. The harness runs the command and writes the evidence. Today the agent writes its own evidence and nothing runs the command. Reverse both: the gate executes run, captures stdout/stderr/exit into evidence, and the row is green if and only if exit is 0. Evidence becomes script-written, which is the rule the harness already applies to checkpoint evidence — where it matters less.
  2. The selector moves into the human's file. One list, one owner, one file. The reconciliation hole closes by not existing.

One file, .context/CONTRACT.md, shipped with the headers and a worked row already in place — not a pointer to a 4,473-word guide:

# CONTRACT — acme-invoices
verify:      make verify          # whole-suite gate; must exit 0 before any ship
base_branch: main

## Never                          # the domain wall guard.sh enforces
exec:     --prod, stripe charge, npm publish
artifact: LIVE_CONFIRMED

## Requirements
| id | the system MUST | falsified by |
| REQ-CFG-01 | reject an unknown config key with a non-zero exit | `nope = 1` starts fine |
| REQ-MON-01 | hold every amount as integer minor units | a float reaches Ledger.post() |

## M0 — configuration spine
| win | name | proves | run | selects | evidence |
| WIN-M0-01 | config-rejects-unknown-key | REQ-CFG-01 | `make win-m0-01` | `tests/test_config.py -k unknown_key` | docs/evidence/M0/01.txt |
| WIN-M0-02 | no-float-in-money-path     | REQ-MON-01 | `make win-m0-02` | —                                 | docs/evidence/M0/02.txt |

Every field gets a named reader: run is executed by the gate, selects feeds the proof map, proves is resolved bidirectionally against the requirement table, evidence is written by the harness. selects: — is deliberate: it marks a row proved by its exit code alone, which fixes a live contradiction where the doctrine calls grep rows "the best WIN rows there are" and the proof map fails any row collecting zero tests. The quickstart's own worked M0 currently cannot pass the ship gate for exactly this reason.

And SPEC.md's fourteen mandatory sections become docs/design.md, unenforced and optional, because no code has ever read any of them.

06

The brake

Cutting is the easy half. Without a mechanical brake this re-inflates in a fortnight, because the pressure that produced it is still there.

The teardown's thesis was that the system pays the agent in documents. That does not change by deleting documents — it changes by changing what scores. Five rules, all checkable:

  1. No markdown ships without a code reader. If no hook parses it, it is a comment, and comments live next to the code they explain. This single rule deletes gap-analysis.md, contracts.md, context.md, research.md, the FAST checkpoints and the recap before anyone argues about them.
  2. A gate asserts a command's exit code, never a file's existence. Every check that currently passes because a file exists — or because its last line reads CLEAR — is deleted or converted. A check that cannot fail is not a check.
  3. Done is a green verify and a merged PR. Not a filed retro, not a consolidated lessons document, not nineteen passing paperwork audits.
  4. One statement, one home. A rule stated twice will drift. The eight mutually incompatible test counts across the shipped docs — three of them in BUILD-NOTES.md alone — are that principle failing in public.
  5. A budget, enforced at review. Hooks ≤ 800 LOC. Prompts ≤ 2,500 words. One README. Exceeding any of them is a design conversation, not a commit.

The agent will produce whatever you score. Score commands.

And one process rule for the rebuild itself: do not let the harness audit the harness again. Four accurate self-diagnoses became four more documents in docs/ and nothing changed. The next assessment of whether this works is a milestone closing, not a report saying it would.

The judgment was never the problem.

red-gate.sh is a genuinely good control and rare to see done properly. The deny list is better-built than most hand-written permission configs I've read. "A WIN row without a verify command is a setup defect, not a judgment call" is the sharpest sentence in 80,250 words. The ownership partition is correct. Somebody here knows what they are doing.

What went wrong is that nothing in the loop could say no. Every gate passed on a file existing, so the only available signal was more — and three days of more is 34,000 lines, twelve seats, an HMAC, and zero delivered milestones. Put one mechanism in place that can return failure, and the same judgment produces a tenth of the code.

Delete first. Write each phase's exit criterion as a command before you start it. Then run M0 — and this time let it fail.
