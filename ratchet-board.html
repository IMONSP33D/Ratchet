Defects — live and reproduced

SubagentStop blocking only sends the finishing subagent back to work; it cannot stop the parent dispatching developer. The gate has to move to PreToolUse on the Agent tool.

Manifest-scope is poisoned by the installer's own filesfix

All 47 harness files land uncommitted and are reported as scope violations on the first Stop. Either commit them or exempt them, and make .gitignore stack-aware.

proof_map returns SKIP with no collector and check_done converts that into a hard FAIL. Every unpacked language and every monorepo is non-shippable, despite the README promising a loud skip.

Every non-Python project silently runs pytestfix

Neither installer writes stack/active, so the runtime always falls back to python-pytest. A node repo records node-jest in metadata and runs python3 -m pytest -q at the gate.

The word "true" anywhere disables three gatesfix

stop_hook_active is substring-matched, and the payload always carries cwd and transcript_path. Use jq — every one of the three files already calls it in the next function.

Force-push to base is allowed by a missing colonto deny[]

+*:* needs a colon, so git push origin +main defeats a rule classified never-escalatable. deny[] already covers the whole family correctly.

F

The brake — so it does not re-inflate

6 rules

Cutting is the easy half. The pressure that produced 34,000 lines is still there unless what scores changes.

No markdown ships without a code readerrule

If no hook parses it, it is a comment, and comments live next to the code they explain. This one rule deletes nine ritual artifacts before anyone argues about them.

A gate asserts an exit code, never a file's existencerule

Every check that passes because a file exists, or because its last line reads CLEAR, is deleted or converted. A check that cannot fail is not a check.

Done is a green verify and a merged PRrule

Not a filed retro, not a consolidated lessons doc, not nineteen passing paperwork audits.

One statement, one homerule

A rule stated twice will drift. Eight mutually incompatible test counts across the shipped docs — three in one file — are this failing in public.

A budget, enforced at reviewrule

Hooks ≤ 800 LOC, prompts ≤ 2,500 words, one README. Exceeding any of them is a design conversation, not a commit.

Do not let the harness audit the harness againrule

Four accurate self-diagnoses became four more documents in docs/ and nothing changed. The next assessment is a milestone closing, not a report saying it would.

Order of operations: group B first (one day, proves the architecture), then C in a single commit, then D. A is mostly resolved by C — only seven of the twenty defects need a deliberate fix once the deletions land.
